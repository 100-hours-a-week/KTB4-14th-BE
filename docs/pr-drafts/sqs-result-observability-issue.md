# [Feat] SQS Result 수신·처리 구간 관측 로그 추가

## 📋 기능 요약

- 여행 생성 Result 메시지의 수신부터 처리·커밋·삭제까지 시간을 나누어 기록해 지연과 반복 수신의 발생 구간을 확인한다.

## 📌 상세 설명

- SQS-05에서 Mock 동시성 3·지연 30초로 동시 생성 10건을 실행했고, 접수·완료·일정 조회는 모두 성공했다.
- Mock은 약 120초에 전 작업을 완료했지만, 일부 결과의 BE 완료 로그가 최종 전송 성공보다 60~122초 늦게 기록됐다.
- 작업 2258의 완료 메시지는 `receive_count=3`으로 처리됐고, 성공한 Inbox 처리 구간은 약 55ms였다. 기존 완료 로그와 DB 기록만으로 이전 수신·실행기 대기·파싱·DB 잠금·커밋을 구분할 수 없다.
- 원인을 단정하거나 처리 설정을 변경하기 전에 각 구간을 관측할 수 있게 한다.

- **✅ 작업한 내용 :**
- [x] 실제 소비 설정, SQS 메시지 전송·첫 수신 timestamp, BE 수신 시각과 수신 횟수 기록
- [x] 최종 메시지 본문의 UTF-8 바이트 수 및 실행기 대기·파싱 시간 기록
- [x] Inbox 조회·저장, 작업 행 잠금, 결과 반영, 트랜잭션·커밋·SQS 삭제 구간 기록
- [x] 실패·롤백·삭제 실패를 구분하고 기존 예외 전파·재시도 정책 유지
- [x] 커밋 실패 시 미삭제, 대기 중 수신 이력, 배치 수신 로그 순서, 민감 정보 미기록 회귀 테스트
- [x] 한국어 로그 해석·재측정 절차·CloudWatch 쿼리 문서 작성
- [ ] dev BE 배포 후 같은 VU 10·총 10건으로 지연 구간 재확인
