### 📌 PR 요약

SQS-05에서 일부 결과가 Mock의 전송 성공 이후 BE 완료 처리까지 60~122초 지연됐으나, 기존 로그로는 수신·내부 대기·파싱·DB 처리 구간을 구분할 수 없었습니다.

Result 메시지의 수신 이력과 단계별 경과 시간을 기록해 반복 수신과 지연이 발생한 구간을 추적할 수 있게 합니다. 이번 변경은 원인 규명을 위한 계측이며 지연 자체를 해결한 변경은 아닙니다.

### 📌 작업 세부 내용

1. 수신 이력과 메시지 크기 기록
   - 실제 Result 소비 설정과 수신 응답 직후의 메시지 ID·수신 시각·수신 횟수 기록
   - SQS `SentTimestamp`·`ApproximateFirstReceiveTimestamp` 요청 및 UTF-8 본문 바이트 수 기록
   - 실행기 제출 전에 배치 전체의 수신 이력을 기록해 poller 직접 처리 시에도 기준 시각 유지
2. 처리·트랜잭션·삭제 구간 측정
   - 실행기 대기·파싱·Inbox 중복 조회 및 저장·작업 행 잠금·결과 반영 구간 기록
   - Spring 트랜잭션 프록시 반환까지 측정하고 커밋 콜백의 COMMITTED·ROLLED_BACK·UNKNOWN 구분
   - SQS 삭제 시간, 수신부터 삭제 완료까지의 시간 및 실패 구간 기록
   - 메시지 원문·토큰·receipt handle은 신규 관측 로그에서 제외
3. 검증 및 운영 문서
   - 커밋 실패 시 미삭제, 내부 대기 중 선행 수신 기록, 잘못된 시각 속성, 배치 처리 순서, 삭제 실패 회귀 검증
   - Java 21 기준 여행 도메인 테스트 **109개 통과**, 실패·오류·건너뜀 0건
   - `./gradlew test --tests 'com.audigo.domain.travel.*' bootJar --console=plain` 검증 성공
   - 한국어 로그 해석·CloudWatch 쿼리·VU 10 재측정 절차 문서화
